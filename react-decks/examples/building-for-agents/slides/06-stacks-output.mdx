<Notes>
OPENING
- A failed stacks verify on my terminal.
- Passed steps green, failed pink, broken lines under each failure, last line says what to do next.
- Printed only when stdout is a terminal, no agent is detected, CI is not set.

[click] CLICK 1
- Same command with CLAUDECODE set, the variable Claude Code puts in the environment.
- No colour codes. Stderr gets one short line as each step starts, in place of the step's live output.
- Picked without a flag: it checks each agent's env vars and AI_AGENT, the cross-agent convention.
- Also used when stdout is a pipe or CI is set.

[click] CLICK 2
- With the JSON flag, stdout is one JSON object. stacks schema prints its schema.
- On failure the last stderr line is an error envelope: tag, message, retryable, next.
- Next is a sentence for the caller. For verify: fix the code or config, leave the steps alone.

[click] CLICK 3
- Each exit code means one thing. The table is in the docs.
- 2 fix the input. 4 retry later. 5 read the verify report on stdout. 6 ask a person.
- An agent branches on the number. A published code never changes meaning.

IF ASKED
- Why not always JSON? People run these too. All three formats render from one result value.
- What exits 6? A refused write, a failed update, or an agent passing the accept-changes flag.
</Notes>
