<Notes>
OPENING
- OpenData is a catalog of public data sources an agent can search and query with SQL.
- Engine is Python and DuckDB. The part an agent talks to is an MCP server in TypeScript, on Bun with Hono.
- Code: the server's tool list, one register call per tool, fourteen in all.
- Model can call eleven. The last three are app only, for the chart interface.

[click] CLICK 1
- On connect the server sends instructions. The highlighted line sets the order: search, SQL, chart.
- Same line: search results include column schemas, so no describe call first.
- Recorded session: one search, one query, 51 rows in 11 ms.
- I tune these instructions from transcripts of real sessions.

[click] CLICK 2
- The chart tool's result has three fields.
- Content: text the model reads.
- Structured content: chart spec and the first 24 rows.
- Underscore meta: the rows the chart draws from, up to 120. Host passes it to the interface, keeps it out of the model's context.
- Query results are limited the same way: 60 rows for the model.

[click] CLICK 3
- Interface is a React app published as a ui resource. The host loads it in an iframe in the conversation.
- Eight bars: rows from this slide's query, the eight jurisdictions it labels PJM-core.
- OpenChart draws it.

IF ASKED
- Why keep rows from the model? Rows cost tokens. The model needs text to describe the result, the chart needs all its rows.
- Host drops underscore meta? Interface draws from the 24 rows in structured content.
- All government sources? No. A few providers aren't, so I say public data sources.
</Notes>
