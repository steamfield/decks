<Notes>
OPENING
- Source of that CLI: 203 files, about 24,000 lines of TypeScript, written with Effect.
- Four Effect ideas in real files. First, where a run begins.
- bin.ts is the only file that imports from Node. A lint rule fails the build otherwise.
- main.ts turns errors into exit codes. cli.ts assembles the commands.

[click] CLICK 1
- The whole runs command.
- Handler gets two services with yield star, calls a function in core, hands the result to Output.
- Output formats for a person or an agent, so the command prints nothing itself.
- Help text lists exit codes because agents read help.

[click] CLICK 2
- A service is a named interface. Host gives platform and working directory.
- Two constructors: layer wraps the real process, memory builds a fake for tests.

[click] CLICK 3
- A layer builds a service. This function composes them all: config, output, logging, processes.
- Production and tests both call it. Tests pass a fake environment.
- A command that needs a service no layer provides fails to compile.

[click] CLICK 4
- Errors are tagged values.
- Each tag has a row: exit code, retryable, report on stdout or not.
- The satisfies clause makes the compiler require a row for every error class.

[click] CLICK 5
- Test builds an HTTP client that returns 503 and provides it as a layer.
- Runs the real update command, compares the JSON error, including the next field.
- No module mocks in the repo.

IF ASKED
- Why Effect? Typed errors, compiler-checked dependencies. Output is a contract with agents, so I can list every way a command fails.
- Which Effect? Effect 4 with its bundled CLI module. Node 22 or newer, Bun builds and bundles.
</Notes>
