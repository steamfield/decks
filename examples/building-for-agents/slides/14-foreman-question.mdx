<ForemanQuestionStage />

<Notes>
OPENING
- A delegate asks by calling a tool: ask_orchestrator, registered with Codex.
- When the model calls it, Codex sends the daemon a JSON-RPC request.
- This code is the daemon receiving that request.
- It stores the request id, records QuestionAsked, sets the run to waiting.
- It sends no response. Codex blocks the turn until the tool call gets one.

[click] CLICK 1
- Claude hears about it through a background foreman wait, started with the delegates.
- Daemon's wake function, six lines: replace a Deferred, resolve the old one, release every waiting wait.
- Wait prints the question and the answer command, then exits.
- Claude Code reports any finished background task to Claude. I use that to deliver the question.

[click] CLICK 2
- Claude runs foreman answer with the question id and the text.
- Daemon finds the stored request id and sends the JSON-RPC response as the tool result. Same turn continues.
- No answer in 15 minutes: daemon tells the delegate to continue with work that doesn't depend on it.
- A late answer arrives as a new message.

[click] CLICK 3
- Test for the timeout: one-second question timeout, wait for the waiting state.
- TestClock.adjust moves Effect's clock one second. Check the question log ends with a Deferred entry marked timeout.
- Codex in these tests is a 117-line Node script replaying a scripted scenario.

IF ASKED
- What if Claude is busy? The question stays pending in the run's question log. foreman status lists it.
</Notes>
