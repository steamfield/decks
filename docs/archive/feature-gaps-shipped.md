# Feature gaps that shipped

Rows moved out of `../feature-gaps.md` once they landed, kept so the original reasoning stays
findable. The test under "Proved by" covers each issue's "done when", and the issue is closed.

| Gap | Slidev feature | Why it mattered | Rough size | Proved by |
| --- | --- | --- | --- | --- |
| Deck-supplied MDX plugins ([steamfield/decks#2](https://github.com/steamfield/decks/issues/2)) | (implicit in Slidev's markdown-it and Vite setup) | `deck.config.ts` has `vite` but no way to add remark or rehype plugins, and the framework owns the MDX plugin. This blocks most of the Recipe list below (math, diagrams, code highlighting chosen by the deck). Add `mdx: { remarkPlugins, rehypePlugins }`. | Small | `e2e/mdx-plugins.spec.ts`, `packages/node/src/dev/plugins-mdx.test.ts` |
| Code blocks ([steamfield/decks#3](https://github.com/steamfield/decks/issues/3)) | Shiki highlighting, line numbers, max height, line highlighting by click, code groups, import code snippets | A fenced code block in a slide renders as unstyled `<pre>` today. Any technical talk needs highlighting, and click-driven line highlighting is one of Slidev's most used features. It fits the step model: a `<Code>` component with `steps` ranges on `data-step-state`. | Medium | `e2e/code.spec.ts`, `packages/motion/src/code-block.test.tsx` |
| Global layers ([steamfield/decks#6](https://github.com/steamfield/decks/issues/6)) | Global Layers (`global-top`, `global-bottom`, per-slide layers) | Elements that persist across slides: a logo, a progress bar, a footer, a background that does not transition with the slide. The kit needs one for its credit layer, so the framework should own the mechanism (`layers/` in a deck or theme, rendered outside the transitioning slide). | Small | `e2e/layers.spec.ts`, `packages/node/src/dev/layers.test.ts` |
| Layouts ([steamfield/decks#7](https://github.com/steamfield/decks/issues/7)) | Built-in layouts (`two-cols`, `image-right`, `center`, `cover`, `section`, ...) and slot sugar | Dropped because the decks here use one layout and CSS classes. A deck written from scratch by an agent benefits from a few named layout components (`<TwoCol>`, `<Center>`, `<Cover>`) more than from CSS it has to invent. Belongs in the default theme. | Small | `e2e/layouts.spec.ts`, `packages/runtime/src/layouts/layouts.test.tsx` |
| Open Graph image ([steamfield/decks#12](https://github.com/steamfield/decks/issues/12)) | Open Graph Image | SEO meta tags are planned with the entry plugin; generating the image from slide 1 with `shot` is the missing piece. | Small | `packages/node/src/dev/browser.test.ts`, `packages/node/src/dev/entry-html.test.ts` |
| Code morphing ([steamfield/decks#4](https://github.com/steamfield/decks/issues/4)) | Shiki Magic Move | The Slidev feature people show off. `shiki-magic-move` has a framework-neutral core and a React renderer; it belongs in the motion package next to `Morph`. | Medium | `e2e/code-magic-move.spec.ts`, `packages/node/src/mdx/magic-move.test.ts` |
| Hand-drawn marks ([steamfield/decks#5](https://github.com/steamfield/decks/issues/5)) | Rough Markers (`v-mark`) | Underline, circle, box, strike-through and bracket drawn on a click. `Highlight` covers only the marker sweep. Rough Notation is framework-neutral; these would be step primitives (`<Mark kind="circle" at={2}>`). | Small | `e2e/motion-mark.spec.ts`, `packages/motion/src/mark.test.tsx` |
| Go-to dialog and navigation components ([steamfield/decks#9](https://github.com/steamfield/decks/issues/9)) | `g` go-to dialog, `<Toc>`, `<Link to>`, slide number components | Small presenter conveniences. `useDeck()` already exposes what they need. | Small | `e2e/go-to.spec.ts`, `packages/runtime/src/slides/toc.test.tsx` |
| Live terminal ([RFC 0008](../rfcs/0008-live-terminal.md)) | (none; `slidev-addon-liveshell` wraps ttyd and breaks in a build) | A talk about CLI tools has to leave the deck to run one. `examples/building-for-agents/term/` runs prepared commands in a real shell from the dev server, with a recording everywhere else, and is written to move into `core`, `node` and `kit` unchanged. | Medium: the code exists; the work is the config field, the kit component split and a Windows answer | `e2e/live-term-shell.spec.ts`, `packages/node/src/term/sessions.test.ts` |
