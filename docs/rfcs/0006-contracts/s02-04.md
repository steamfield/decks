## Hard rules

- Each slide gets a story stage `components/<Name>Stage.vue` on `useStage`.
- `COPY` length equals the beat count in `OUTLINE.md`. `slides.md` already declares `clicks:` as beats minus 1. Don't edit `slides.md`. If a slide genuinely needs a different beat count, use it and say so in the hand-off: the orchestrator updates the manifest.
- Card lead is 8 words at most; body is 20 at most. Headlines are one claim ending in a period.
- No em dashes. No jargon or statute numbers on screen. Party is always a text label.
- No hex values, `px` radii or opacity literals in components. Use `ink()` or the helpers in `design.ts`, `var(--od-*)` or `var(--tx-*)`, and `design.ts` constants. Durations come from `DUR`. Frame units are `--sw`/`--sh`.
- Print the evidence status as a word on the object (`tx-tag is-pending`, `is-reported`, `is-scenario`).
- Each page `pages/NN-slug.md` is the slide comment header, then a presenter-notes HTML comment (an opening paragraph plus one `[click]` paragraph per beat, each speakable in about 25 seconds), then `<NameStage />`.
- Use the sources from `data-sources.md` for the `StoryLink` on each slide.

From the worktree root, iterate until clean:

```bash

```

Then QA every slide you own as the audience would see it:

1. Start a dev server on your port: `bun run dev tx26 --port 3041 &`, then `wait-for 3041`. Restart it after adding any component file.
2. Run `bun run shot <n> <click> 3041` for every click of every slide you own. Look at every PNG.
3. Check that:
   - nothing overlaps or clips;
   - text is readable at the back of a room;
   - one thing changes per beat;
   - the card lead matches `COPY`;
   - `errors: none`.
4. Step backward through each slide too: shot click 3, then click 1. The frames must match the forward pass.
5. Fix what you find.
6. Before finishing, run `bun run build tx26` once.
