If you want to build slides in React in late 2026, four React-based projects are maintained and worth a look: Spectacle, reveal.js through its official React bindings, ReMDX and Decks. Spectacle is the longest-running of them and a good general pick for slides written as JSX. reveal.js has the deepest feature set and plugin ecosystem, and `@revealjs/react` now lets you drive it from React components. ReMDX is a small MDX-first option. Decks, which this site is for, is built for animated data talks and for decks written with a coding agent.

Two names that still show up in search results are a poor choice for new work. MDX Deck's last npm release was 4.1.1 in March 2020, and MDXP's repository is archived. Slidev is actively maintained, but it's built on Vue, so your slide components are Vue components.

## How do the React presentation frameworks compare?

## Spectacle

[Spectacle](https://github.com/FormidableLabs/spectacle), from Formidable, is the longest-running React-native slide library and still actively maintained. A deck is a tree of components: `Deck`, `Slide`, `Heading`, layout primitives and so on. If you'd rather write prose, `MarkdownSlideSet` splits Markdown on `---` into slides, and the `spectacle-mdx-loader` package adds MDX.

Step reveals use `Appear` for one element and `Stepper` for a value that changes across several steps; both are built on a `useSteps` hook you can use for your own components. Presenter mode runs in a second browser window on the deck's local server, opened with `Alt+Shift+P` or `?presenterMode=true`, and shows notes, a timer and the next slide. PDF export goes through the browser's print dialog: open the deck with `?exportMode=true` and print to PDF.

Pick Spectacle for a general slide deck in JSX, styled with your own components and theme, when you're happy wiring up anything specialized yourself.

## reveal.js with React

[reveal.js](https://revealjs.com/) is the most established HTML presentation framework, with nested vertical slides, a large plugin ecosystem, Markdown support, stepped code highlights, Auto-Animate between slides and careful PDF export. Version 6 added official React bindings, [`@revealjs/react`](https://revealjs.com/react/): `Deck`, `Slide`, `Stack` for vertical slides, `Fragment` for step reveals, `Code`, `Markdown` and a `useReveal()` hook.

The bindings are only bindings. You still import reveal.js's CSS, a theme and the plugins you want, and the behavior underneath is reveal.js's, which helps if you already know it. Speaker view opens in a separate window with `S`. PDF export is `?print-pdf` plus the browser's print dialog, which the docs confirm in Chrome and Chromium; `decktape` does it from the command line.

Pick reveal.js when you need its feature depth or plugins, or your team already has reveal.js decks, and you want to write new slides as React components. The React bindings are at 0.2, so expect API changes.

## ReMDX

[ReMDX](https://github.com/nkzw-tech/remdx) describes itself as minimalist presentations with React and MDX. It requires React 19, scaffolds with `npm init remdx` and runs as a Vite plugin. Its README gives Slidev's Vue base as the reason it exists.

Pick it when you want plain MDX slides in a modern React and Vite setup with as little framework as possible.

## Decks

Decks (`@steamfield/decks`) is a React 19 slide framework for animated, data-driven talks. A deck is a directory: one MDX file per slide in `slides/`, React components in `components/` that every slide can use without importing, and a `deck.config.ts`. Slides are drawn on a 1920 by 1080 canvas that scales to any window, and the click count for each slide is read from the source at build time.

What it adds over the others is aimed at data and live-code talks. `ChartSteps` animates a chart from one data state to the next on each click, and story stages keep one SVG figure on screen and change it per click with a caption that changes alongside. A `LiveTerm` pane runs prepared commands in a real shell on the speaker's machine, with a recording as the fallback. `decks dev talk --remote` serves notes and controls to a phone or iPad, which helps when the laptop is mirrored to the projector.

Decks also ships coding-agent support: `decks init` sets up a Claude Code plugin and Codex skills for structure, slide prose, motion, charts and sourcing figures, and CLI checks such as `decks inspect` (text that leaves the canvas) let an agent verify its own work.

Pick Decks when the talk's argument lives in charts that change as you speak, when you want a coding agent to draft and revise the deck, or when you present live commands. Skip it if you need light-themed slides out of the box (the kit theme ships dark and its charts always draw dark) or an editable PowerPoint file; it exports PDF and PNG.

## What happened to MDX Deck?

[MDX Deck](https://github.com/jxnblk/mdx-deck) made MDX slides popular: one `.mdx` file, slides separated by `---`, React components inline. Its last npm release was 4.1.1 on March 12, 2020, and the repository's last commit was in 2021, so a new project would start on dependencies from 2020. MDXP, a similar project, has an archived repository and a last release in 2020 that peers on React 16.

If you liked MDX Deck's model, ReMDX and Decks are maintained MDX-based alternatives, with different scopes.

## Is Slidev a React framework?

No. [Slidev](https://sli.dev/) is built on Vue and Vite, and its components are Vue single-file components. It has a presenter mode, recording, drawing on slides, and a `--remote` flag that serves the presenter view to other devices. If you're comfortable in Vue, or your slides are mostly Markdown, it's a strong choice; this site has a [Slidev versus Marp comparison](/blog/slidev-vs-marp/).

The cost for a React developer comes when slides need components. A chart, a diagram or a demo you've already built in React has to be rewritten or wrapped to run in Vue. Decks started as a Slidev addon and moved to its own React runtime for that reason.

## Can you build slides in React without a framework?

Yes, for a short talk. A slide deck is a list of full-screen components, an index in state and a key handler, and an animation library such as Motion covers transitions. The work piles up in what frameworks handle for you: a presenter window kept in sync with the audience window, speaker notes, PDF export, scaling a fixed canvas to any screen, and a URL that remembers your position. If you need two or more of those, start from one of the frameworks above.

To try Decks, the [quickstart](/docs/getting-started/quickstart/) gets a deck running with three commands.
